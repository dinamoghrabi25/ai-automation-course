# RAG vs. Tool Calling
## الوكيل الذكي العقاري

### 1. الفكرة الأساسية

يعتمد اختيار التقنية على هدف المهمة:

- **RAG:** استرجاع معلومات موثوقة من قاعدة معرفة للإجابة عن الأسئلة.
- **Tool Calling:** استخدام أداة لتنفيذ إجراء فعلي في نظام متصل.

### 2. ما هو RAG؟

اختصار لـ Retrieval-Augmented Generation، أي التوليد المعزّز بالاسترجاع.

تسمح هذه التقنية للوكيل بالبحث في مصادر المعرفة، مثل سياسات الشركة وشروط البيع والتقسيط، ثم استخدام المعلومات المسترجعة لتقديم إجابة مناسبة.

**مثال عقاري:**

يسأل العميل: «ما شروط شراء شقة بالتقسيط؟»

يبحث الوكيل في قاعدة المعرفة عن شروط التقسيط المعتمدة، ثم يشرحها للعميل.

**الهدف:** توفير إجابة مبنية على معلومات موثوقة.

### 3. ما هو Tool Calling؟

هو استدعاء الوكيل الذكي لأداة متصلة لتنفيذ مهمة محددة، مثل حفظ البيانات أو تسجيل طلب أو حجز موعد.

**مثال عقاري:**

يؤكد العميل بياناته ويوافق على حفظها، فيستدعي الوكيل أداة لحفظها في قاعدة بيانات العملاء، ثم يتحقق من نجاح العملية.

**الهدف:** تنفيذ إجراء فعلي بدل الاكتفاء بتقديم إجابة نصية.

### 4. الفرق بين RAG وTool Calling

| وجه المقارنة | RAG | Tool Calling |
|---|---|---|
| الهدف | استرجاع المعرفة | تنفيذ إجراء |
| الاستخدام | الإجابة عن الأسئلة | تنفيذ المهام |
| مثال | شرح شروط التقسيط | حفظ بيانات العميل |
| النتيجة | إجابة مبنية على المعلومات | نتيجة عملية في نظام متصل |

### 5. أدوات يمكن أن يستخدمها الوكيل العقاري

1. **Property Search Tool:** البحث عن العقارات حسب الموقع والميزانية وعدد الغرف.
2. **Database Tool:** حفظ بيانات العملاء وطلبات العقارات.
3. **Appointment Tool:** حجز مواعيد لزيارة العقارات.
4. **Notification Tool:** إرسال تأكيدات وإشعارات للعملاء.
5. **CRM Tool:** تسجيل اهتمام العملاء بالعقارات ومتابعة طلباتهم.

**أمثلة على الخدمات:**
- Supabase أو PostgreSQL لإدارة قواعد البيانات.
- Google Calendar لإدارة المواعيد.
- n8n لربط الخدمات وتنفيذ سير العمل.

هذه أمثلة على خيارات ممكنة وليست متطلبات إلزامية للمشروع.

### 6. مثال يجمع التقنيتين

إذا أراد العميل حجز شقة:

1. يستخدم الوكيل **RAG** لاسترجاع شروط الحجز من قاعدة المعرفة.
2. يشرح الشروط للعميل ويجمع المعلومات المطلوبة.
3. بعد استيفاء الشروط والحصول على التأكيدات اللازمة، يستخدم **Tool Calling** لتسجيل طلب الحجز.
4. يتحقق من نتيجة التنفيذ ويخبر العميل بحالة الطلب.

في هذا السيناريو، تساعد RAG الوكيل على معرفة المعلومات المطلوبة، بينما تساعده Tool Calling على تنفيذ الإجراء.

### 7. تطبيق الفكرة باستخدام Dify وn8n

- **Dify Knowledge Base:** تخزين سياسات الشركة وشروط البيع والشراء.
- **Dify Agent:** فهم طلب العميل وتحديد ما إذا كان يحتاج إلى معلومات أو إجراء.
- **n8n Workflow:** تنفيذ مهام مثل حفظ البيانات أو حجز موعد أو إرسال إشعار.
- **Supabase:** تخزين بيانات العقارات والعملاء والطلبات عند الحاجة.

يمكن ربط Dify بـ n8n من خلال API أو وسيلة تكامل مناسبة، بعد إعداد الاتصال والصلاحيات اللازمة.

### 8. الخلاصة

نستخدم **RAG** عندما يحتاج الوكيل إلى استرجاع معلومات موثوقة للإجابة عن سؤال، ونستخدم **Tool Calling** عندما يحتاج إلى تنفيذ إجراء في نظام متصل.

يمكن الجمع بين التقنيتين في وكيل واحد ليقدم معلومات موثوقة وينفذ الإجراءات المناسبة.

**ملاحظة أمنية:** يجب التحقق من البيانات والموافقات والصلاحيات قبل تنفيذ الإجراءات، وعدم تأكيد نجاح الحفظ أو الحجز إلا بعد التحقق من نتيجة الأداة.
